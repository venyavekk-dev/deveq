# Ship Safe Pull Request

`Ship Safe Pull Request` — это скилл для Codex и Claude Code. Он объясняет агенту, как безопасно изменить проект, проверить результат, создать pull request и остановиться перед слиянием.

Если совсем коротко: вы описываете задачу, а скилл помогает довезти её до готового PR, ничего не потерять и не слить изменение без вашего разрешения.

## Что такое скилл

Скилл — это папка с инструкцией `SKILL.md`. В ней записано, как агент должен выполнять определённый тип задач.

Без скилла агент каждый раз сам решает:

- где редактировать файлы;
- как назвать ветку;
- какие проверки запустить;
- как оформить PR;
- нужно ли показывать превью;
- можно ли сразу выполнить merge.

Со скиллом основные решения уже зафиксированы. Агенту не нужно заново угадывать ваш рабочий процесс.

## Почему Ship

В разработке слово `ship` означает «доставить изменение пользователям».

Можно представить задачу как груз:

1. Задача принимается на борт.
2. Для неё создаётся отдельное безопасное рабочее место.
3. Изменение реализуется и проверяется.
4. Результат упаковывается в pull request.
5. Пользователь осматривает PR и превью.
6. Только после разрешения груз прибывает в `main`.

Скилл отвечает не только за написание кода, но и за безопасную доставку результата.

## Что означают незнакомые слова

### Репозиторий

Папка проекта вместе с историей изменений Git.

### Основная ветка

Главная версия проекта. Обычно она называется `main`.

### Ветка задачи

Отдельная линия изменений. Она позволяет подготовить новую работу, не меняя `main` напрямую.

### Worktree

Отдельная рабочая папка Git для конкретной задачи.

Worktree нужен, чтобы один агент не стёр незакоммиченные изменения другого агента или пользователя в общей папке. По умолчанию скилл требует выполнять любые изменения файлов в отдельном worktree.

### Коммит

Сохранённая порция изменений с коротким описанием. Несколько небольших понятных коммитов легче проверить, чем один огромный.

### Pull request, или PR

Страница на GitHub, где видно:

- что изменилось;
- зачем это сделано;
- какие файлы затронуты;
- какие проверки выполнены;
- можно ли безопасно добавить изменение в `main`.

### Preview

Временная версия сайта для проверки изменения до merge. Если проект использует Vercel, для PR обычно создаётся отдельная ссылка на Vercel-превью.

### Merge

Добавление изменений из ветки задачи в основную ветку. Скилл запрещает выполнять merge без отдельного явного разрешения пользователя.

## Что происходит после запуска скилла

1. Агент читает применимые `AGENTS.md`, `CLAUDE.md` и `SKILL.md`.
2. Кратко объясняет, что собирается сделать и как проверит результат.
3. Ждёт подтверждения плана.
4. Проверяет репозиторий, ветки, remotes, worktree и незакоммиченные изменения.
5. Получает актуальное состояние удалённой основной ветки.
6. Создаёт отдельный worktree и уникальную ветку задачи.
7. Вносит только согласованные изменения.
8. Запускает подходящие тесты, lint, typecheck, сборку или другие проверки проекта.
9. Просматривает diff и делает небольшие осмысленные коммиты.
10. Отправляет ветку на GitHub и создаёт PR с явно указанными исходной и основной ветками.
11. Находит и показывает Vercel-превью или другую ссылку на временную версию, если она доступна.
12. Показывает итоговый отчёт: результат, PR, превью, проверки, ветку, коммиты и риски.
13. Просит разрешение на merge конкретного PR.
14. Выполняет merge только после разрешения и только при отсутствии новых блокирующих проблем.

## Как выглядит итоговый отчёт

После создания PR агент должен прислать самостоятельный отчёт примерно такого вида:

```text
Результат — добавлен экспорт отчёта в CSV.
Pull request — https://github.com/example/project/pull/42
Preview — https://example-git-feature.vercel.app
Проверки — tests: passed; lint: passed; build: passed.
Git — ветка codex/add-csv-export; коммит a1b2c3d.
Риски — не обнаружены.
Merge — разрешаете слить PR № 42 в main?
```

После каждого нового push агент должен снова прислать полный отчёт с актуальной ссылкой на превью и новым состоянием проверок. Пользователю не нужно искать ссылки в старых сообщениях.

## Что скилл делает автоматически

- читает правила проекта;
- согласовывает план до начала реализации;
- изолирует работу в отдельном worktree;
- создаёт отдельную ветку;
- сохраняет чужие и незакоммиченные изменения;
- запускает доступные проверки;
- делает понятные коммиты;
- составляет заголовок и описание PR;
- показывает ссылку на PR;
- показывает актуальное превью;
- сообщает о неудачных проверках и рисках;
- останавливается перед merge.

## Чего скилл не должен делать

- начинать реализацию до подтверждения плана;
- редактировать общую рабочую папку без явного разрешения;
- переключать в общей папке ветки ради новой задачи;
- использовать там `git stash`, `git reset`, `git clean`, `git checkout --` или похожие команды для подготовки работы;
- стирать, прятать или коммитить чужие изменения;
- добавлять несвязанный рефакторинг;
- менять дизайн без запроса;
- утверждать, что незапущенная проверка прошла;
- скрывать ошибку сборки или отсутствие превью;
- выполнять merge только потому, что проверки зелёные;
- выполнять merge без разрешения пользователя на конкретный PR.

## Как установить в Codex

Можно попросить Codex установить скилл прямо из GitHub:

```text
Установи скилл из https://github.com/venyavekk-dev/deveq/tree/main/ship-safe-pull-request
```

Для ручной установки скопируйте папку в личный каталог скиллов:

```bash
cp -R ship-safe-pull-request ~/.codex/skills/ship-safe-pull-request
```

После установки начните новую задачу или обновите рабочую сессию, чтобы скилл появился в списке.

## Как установить в Claude Code

Для одного проекта скопируйте папку сюда:

```text
<project>/.claude/skills/ship-safe-pull-request/
```

Для всех проектов пользователя используйте личный каталог:

```text
~/.claude/skills/ship-safe-pull-request/
```

Claude Code использует `SKILL.md`. Файл `agents/openai.yaml` относится к интерфейсу Codex и не мешает Claude Code.

Если в проекте есть `CLAUDE.md`, он может подключить общие правила из `AGENTS.md`, как это сделано в репозитории `deveq`.

## Как запустить

Укажите скилл явно и добавьте задачу:

```text
Используй $ship-safe-pull-request, чтобы добавить экспорт отчёта в CSV и подготовить PR.
```

```text
Используй $ship-safe-pull-request, чтобы исправить ошибку авторизации. Проверь тесты и остановись перед merge.
```

```text
Используй $ship-safe-pull-request, подготовь PR и пришли актуальную ссылку на Vercel-превью.
```

Агент также может выбрать скилл автоматически, если запрос явно связан с реализацией изменения и его доставкой через pull request.

## Если Vercel не подключён

Отсутствие Vercel не блокирует работу. Агент должен прямо написать, что превью недоступно, и перечислить проверки, которыми подтверждён результат: например, тесты, lint, typecheck, сборку или безопасный HTTP-запрос.

## Если в общей папке уже есть изменения

Агент не должен их трогать. Он создаёт новый worktree от актуальной удалённой основной ветки и выполняет задачу там.

Если задача должна продолжить именно эти незакоммиченные изменения, агент сначала согласовывает с пользователем безопасный способ работы.

## Настройка под конкретный проект

Проектные `AGENTS.md` и `CLAUDE.md` могут дополнительно определить:

- формат названия ветки;
- обязательные проверки;
- правила оформления коммитов и PR;
- способ получения Vercel-превью;
- дополнительные точки подтверждения;
- исключения, явно разрешённые пользователем.

Самые конкретные правила проекта дополняют общий процесс скилла.

## Что находится в папке

```text
ship-safe-pull-request/
├── README.md
├── SKILL.md
└── agents/
    └── openai.yaml
```

- `SKILL.md` — основная инструкция для агента.
- `agents/openai.yaml` — название, описание и стартовый запрос для интерфейса Codex.
- `README.md` — эта инструкция для человека.
