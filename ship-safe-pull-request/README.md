# Ship Safe Pull Request

Скилл для безопасной доставки небольших, целевых изменений через pull request. Он помогает Codex пройти весь путь от согласованного плана до готового к ревью PR, не затрагивая посторонние изменения и не выполняя merge без явного разрешения пользователя.

## Когда использовать

Используйте скилл, когда нужно:

- реализовать изменение и оформить его отдельным pull request;
- безопасно работать в репозитории с незакоммиченными или параллельными изменениями;
- подготовить небольшие осмысленные коммиты;
- запустить подходящие тесты, lint, typecheck или сборку;
- получить ссылку на Vercel-превью или другое PR-превью;
- остановиться перед merge и передать решение пользователю.

## Установка

Попросите Codex установить скилл из GitHub:

```text
Установи скилл из https://github.com/venyavekk-dev/deveq/tree/main/ship-safe-pull-request
```

Либо скопируйте папку `ship-safe-pull-request` в каталог скиллов Codex:

```bash
cp -R ship-safe-pull-request ~/.codex/skills/ship-safe-pull-request
```

После установки перезапустите или обновите рабочую сессию Codex, чтобы новый скилл появился в списке доступных.

## Использование

Вызовите скилл явно через `$ship-safe-pull-request` и опишите задачу:

```text
Используй $ship-safe-pull-request, чтобы добавить экспорт отчёта в CSV и подготовить pull request.
```

```text
Используй $ship-safe-pull-request для исправления ошибки авторизации. Проверь тесты и остановись перед merge.
```

```text
Используй $ship-safe-pull-request, подготовь PR и пришли ссылку на Vercel-превью.
```

Скилл также может включаться автоматически, когда задача явно требует реализовать изменение и доставить его через pull request.

## Как устроен процесс

1. Прочитать применимые инструкции `AGENTS.md`.
2. Согласовать результат, область изменений и способ проверки.
3. Проверить репозиторий, текущую ветку и незакоммиченные изменения.
4. Создать изолированную ветку или `git worktree`.
5. Реализовать только согласованное изменение.
6. Запустить проверки, соответствующие риску задачи.
7. Просмотреть diff и сделать небольшие осмысленные коммиты.
8. Создать pull request с явно указанными исходной и основной ветками.
9. Найти и сообщить ссылку на превью, если проект его предоставляет.
10. Остановиться перед merge и запросить отдельное разрешение пользователя.

## Гарантии безопасности

Скилл предписывает:

- сохранять посторонние и пользовательские изменения;
- не включать в PR несвязанный рефакторинг;
- не менять дизайн без согласованной задачи;
- не заявлять о проверках, которые фактически не запускались;
- явно указывать ветки при создании pull request;
- не выполнять merge только на основании успешных проверок;
- запрашивать разрешение на слияние конкретного pull request.

## Настройка под проект

Локальный `AGENTS.md` может задавать собственные:

- префиксы и правила именования веток;
- обязательные команды проверки;
- формат коммитов и pull request;
- правила работы с Vercel или другим хостингом;
- дополнительные точки подтверждения.

Проектные инструкции дополняют общий процесс скилла и имеют приоритет в рамках конкретного репозитория.
